# UNANSWERED — 사용자 테스트 + 교수님 피드백 반영 수정

먼저 `AGENTS.md`를 읽고 그 규칙을 그대로 따라줘. 시작 전에 `git status`부터 확인하고, 커밋 안 된 기존 변경은 절대 건드리지 마.
`src/lib/imageAnalysis.js`, `src/lib/lightRenderer.js`는 수정 금지.
`* 2.tsx`, `* 2.css` 같은 중복 파일은 수정하지 말고 원본만 고쳐.

작업은 Phase 1 → 5 순서로 진행해. Phase 하나가 끝날 때마다 `npm run build`가 통과하는지 확인하고, 바꾼 파일 목록을 보고해줘.

## 왜 고치는지

사용자 테스트에서 이런 반응이 나왔어.

- 뭘 기준으로 골라야 할지 모르겠다.
- 정답을 맞혀야 하는 건지, 내 생각대로 해도 되는 건지 모르겠다.
- 중간중간 어려운 문장이 많다.
- 마지막에 "찾던 사람이 나였다"는 반전이 잘 안 와닿는다. 특히 특정 누군가를 떠올리며 고른 사람은 "그건 내 친구 얘긴데?"에서 끝난다.

원인은 하나야. 조사 설정이 '정답이 있는 게임'처럼 읽히는 거야.
그래서 수정 방향은 네 가지야.

1. 정답이 없다는 걸 대놓고 말한다.
2. 각 구역에서 할 일을 한 줄로 알려준다.
3. 문장을 쉽게 바꾼다.
4. 엔딩에서 **고른 것(그 사람의 기록)**과 **고르는 동안 남긴 것(당신의 기록)**을 분리하고, 후자를 실제 기록 재생으로 보여준다.

**톤 원칙**
- 엔딩에서 '분석했다'는 표현은 쓰지 마. '기록했다'까지만 말해. 심리테스트처럼 보이면 안 돼.
- 새로 보이는 UI는 기존 시각 언어를 따라. 거의 무채색 + #8A6BFF 포인트 하나.

## Phase 1 — 규칙 고지 + 할 일 한 줄

### 1-1. 규칙 카드
`RegistrationScene`에서 조사원증 발급이 끝난 뒤, `lightArchive`로 넘어가기 전에 카드를 한 장 보여줘.
씬을 새로 만들지 말고 RegistrationScene 안의 로컬 phase로 추가해. 전역 씬 흐름은 바꾸지 마.

카드 문구:
```
이 사람에 대해 알려진 것은 없습니다.

정답은 없습니다.
오래 생각하지 마세요.
당신 눈에 그렇게 보이면, 그게 단서입니다.

[조사 시작]
```

### 1-2. 구역별 할 일 한 줄
각 체험 씬의 지시문 근처(StageHeader 또는 기존 서브타이틀 자리)에 아래 두 줄을 추가해.
개수(최대 몇 개 등)는 `data/content.ts`의 상수에서 읽어서 표시하고, 하드코딩하지 마.

- 첫째 줄 형식: `할 일 · 사진 1장 고르기`
- 둘째 줄(보조 텍스트, 작게, 모든 구역 공통): `첫 느낌으로 고르세요`

| 구역 | 할 일 |
|---|---|
| 빛 | 사진 1장 고르기 → 느낌 단어 최대 `MAX_EMOTION_KEYWORDS`개 |
| 소리 | 들어보고 1개 고르기 → 거리 표시 |
| 기억 | 흔적이 남은 물건 `MEMORY_MIN_OBJECT_SELECTION`개 이상 고르기 |
| 문장 | 이어질 문장 `SENTENCE_MIN_FRAGMENTS`–`SENTENCE_MAX_FRAGMENTS`개 고르기 |

실제 단계 구성이 위 표와 다르면 코드 기준으로 맞추고, 무엇을 바꿨는지 보고해줘.

### 1-3. 망설임 넛지
선택형 구역(빛, 소리, 기억, 문장)에서 다음 조건을 모두 만족하면 넛지를 띄워.

- 마지막 입력(선택, 선택 해제, 재생, 이동) 이후 8초 동안 새 입력이 없음
- 아직 다음으로 넘어가지 않음

넛지 동작:
- 구역당 1회만 표시
- 화면 하단 중앙에 조용히 페이드인했다가 4초 뒤 사라짐

넛지 문구:
```
오래 고민하지 않아도 됩니다.
대답하지 못한 것도 기록됩니다.
```

주의:
- 넛지는 순수 표시용이야. tracker 이벤트 로그에 아무것도 기록하지 마. 저장 데이터 구조도 바꾸지 마.
- `prefers-reduced-motion`이면 페이드 없이 표시해.

### 1-4. HUD "기록 중" 깜빡임
`ArchiveHUD`에 `기록 중` 표시를 추가하고, 아래 순간에 0.8초 동안 #8A6BFF 점과 함께 깜빡이게 해.

- 선택 해제(deselect)
- 소리 다시 듣기
- 이미 본 선택지로 다시 돌아와 머문 순간(revisit)

구현 방식:
- 씬의 기존 핸들러에서 가벼운 표시용 신호(예: 작은 zustand 플래그나 이벤트 이미터)만 쏘면 돼.
- 저장되는 BehaviorEvent의 형태는 바꾸지 마.

### 2-3. 질문형 문구 — 퀴즈 톤 빼기
"~무엇이었을까요 / ~누구였을까요"는 "~것 같나요?"로 바꿔.

같은 패턴의 질문 전부(`sentenceQuestionService.ts` 포함)에 적용해줘.

## Phase 3 — 엔딩 재구성: 두 겹 보고서

현재 흐름: `clues → (return) → (hesitation) → memory → observation → reveal → archive`
stage key, 조건부 로직, 데이터 계층(`reportStageFacts`, `crossSceneAnalysis`)은 그대로 두고, **문구와 표시만** 바꿔.

### 3-1. Stage01 — 그 사람의 보고서 (3인칭만)
`ReportStage01CollectedClues`에서 '당신'이 들어간 문구를 전부 빼.

| 지금 | 바꿀 문구 |
|---|---|
| 조사를 마쳤습니다. / 그런데, 확인해야 할 것이 하나 남아 있습니다. / 그동안 당신은 생각보다 많은 흔적을 남겼습니다. | `이름 없는 사람에 대한 보고서입니다.` / `이 사람이 남긴 빛, 소리, 문장입니다.` |
| 당신이 남긴 것 | 이 사람의 단서 |
| 다음 흔적 확인 | 계속 |

### 3-2. 전환 비트
return / hesitation / memory 중 **처음으로 나오는 스테이지**의 맨 앞에 전환 비트를 넣어.
- 전체 화면, 텍스트만, 클릭하면 진행
- 조건부 스테이지가 빠져도 반드시 한 번만 나와야 해.

전환 문구:
```
당신은 누군가를 떠올리며 골랐을지도 모릅니다.

그런데 이 보고서에는
고르는 동안 남은 기록이 하나 더 있습니다.
```

`ReportStage06SubjectReveal`에 있던 "당신은 특정한 누군가를 떠올리며 이 기록을 복원했을지도 모릅니다." 문장은 여기로 옮겼으니 06에서는 지워.

### 3-3. 증거 재생 `TraceReplay` 컴포넌트 (핵심)
`src/scenes/report/TraceReplay.tsx`를 새로 만들고, Stage02(return)와 Stage03(hesitation)의 기존 evidence 영역에 넣어.
기존 `ReportEvidenceVisual`은 지우지 말고 재생 아래(또는 재생이 끝난 뒤)에 유지해.

**입력**
- 해당 finding이 가리키는 씬의 `SceneBehaviorRecord.events`

**재생 방식**
- **선택형(view / select / deselect)**
  - 그 구역의 선택지 라벨을 작은 칩으로 나열해.
  - `view` 이벤트 순서대로 하이라이트가 칩 사이를 옮겨 다녀. 각 칩에 머무는 시간은 실제 `durationMs`에 비례하게 하되, 전체 재생 시간은 6초 이내로 압축해.
  - `select`면 칩을 채우고, `deselect`면 채움이 빠지면서 짧게 취소선을 그어.
- **소리**: 소리별 막대로 표시. 재생 횟수만큼 막대가 차오르고, `replayCount > 0`인 소리에는 `다시 들음 ×N`을 붙여.
- **위치(position)**: 기록된 `path`를 필드 위에 실제 경로대로 다시 그려(시간 압축).
- **기억 스케치**: 기록된 stroke `points`를 순서대로 다시 그리고, `strokeRemove`(지운 것)는 흐리게 사라지게 해.

**재생 아래 사실 문장** (숫자는 기록에서 그대로 읽어)
- `빛 구역에서 3장의 사진 사이를 4번 오갔습니다.`
- `「종이 넘기는 소리」를 2번 다시 들었습니다.`
- `한 번 고른 문장을 뺐다가 다시 넣었습니다.`

**재생 컨트롤**
- 재생 끝나면 정지. `다시 보기` 버튼 제공.
- `prefers-reduced-motion`이면 애니메이션 없이 최종 상태만 표시.

**데이터 원칙**
- 새 데이터 수집 금지. 이미 저장된 이벤트만 읽어.
- 선택지 사이의 커서 궤적은 기록되지 않으니 지어내지 마. 하이라이트 이동은 `view` 순서로만 재구성해.
- 기록이 비어 있으면 재생을 숨기고 기존 화면을 보여줘.

### 3-4. 결론 문구
Stage03(hesitation) 마지막 문구, 또는 Stage03이 없으면 memory 스테이지 마지막 문구를 아래로 바꿔.
```
누구를 떠올렸든,
망설인 손은 당신의 것이었습니다.
```

## Phase 4 — Reveal: 첫 영상 인물과 겹치기

`ReportStage06SubjectReveal`의 카메라 옵트인 흐름은 그대로 둬.
카메라를 쓸 때와 쓰지 않을 때 **둘 다** 아래 순서로 연출해.

1. 랜딩에 나왔던 `HeroFigure` 인물이 뒷모습/측면 상태로 다시 등장해. 기존 에셋을 재사용하고, 새 이미지는 만들지 마.
2. 인물 실루엣 안쪽이 관객의 빛 그래픽(LIGHT 결과)과 고른 색으로 서서히 채워져.
3. 조사원증 라벨이 `이름 없음`에서 관객이 입력한 이름으로 바뀌어.
4. 인물이 정면으로 전환돼. 정면 에셋이 없으면 크로스페이드로 대체하고, 어떤 방식을 썼는지 보고해줘.
5. 카메라를 켰다면 이때 실시간 거울 화면이 실루엣 위로 겹쳐져.
6. `당신입니다.`
