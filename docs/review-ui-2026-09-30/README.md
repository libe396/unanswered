## 구현

문장 선택에서는 긴 중복 선택 목록을 없애고 번호 해제 버튼 5칸과 개수만 표시합니다. 5열 × 4행으로 20개 카드를 동시에 보여줍니다. 카드/페이지 스크롤, 페이지 분할, 내용 자르기 없이 표시합니다. 최소 지원 콘텐츠 viewport는 1200×640이며, 그보다 작으면 큰 화면 안내를 표시합니다. CSS로 표시만 전환하므로 선택·입력 상태는 남습니다. 글자 크기는 데스크톱 본문 15–16px입니다.

기록 복원은 헤더·푸터 사이에 최대 520px 높이의 콘텐츠 묶음을 중앙 배치합니다. 카드 프레임과 오른쪽 내용의 기준 위치를 유지합니다. 기록 상태, 빈칸 개수, 단계 설명은 한국어로 표시합니다.

REPORT 01은 1200px에서 960px로 폭을 줄였습니다. 빛 그래픽은 약 325px에서 258px로 약 21% 작아졌고 파형 높이는 150px에서 100px로 줄었습니다. 본문은 16px입니다. 일반 기록은 중앙에서 하단 문구·페이지·버튼까지 한 묶음으로 표시하며, 매우 긴 기록은 내용을 자르지 않고 정상 스크롤합니다. 소리 원본 데이터에는 이름이 없어서 임의 이름 대신 '소리 03'으로 표시합니다.

빛 과정은 기존 `analyzeImage`와 `renderLightGraphic`을 변경하지 않습니다. `brightRegions`의 실제 중심·크기·색, `palette`, `structureAnchors`, `lightOrigin`, `motionDirection`을 표현합니다. 밝은 영역 원은 저장된 중심/크기 표시이며 픽셀 단위 분할 마스크를 가장하지 않습니다. 구조 선·점 다음에는 실제 생성된 결과 캔버스를 순차적으로 드러냅니다. 새 랜덤 입자나 가짜 진행률은 없습니다. 계산과 그리기 시간을 고려한 첫 진입은 브라우저에서 약 7.9초로 측정했습니다. 재생은 같은 결과 데이터를 재사용하며 재분석하지 않습니다. 모션 감소는 같은 순서를 정적인 전환으로 보여줍니다.

## 검증

- Chromium의 실제 콘텐츠 viewport 1440×900, 1366×768, 1280×640: 20개 카드/다음 버튼 모두 표시. 페이지 및 카드 내부 스크롤 없음, 잘림 없음. 0개/5개/선택 해제의 버튼 Y 좌표 동일.
- 최소 1200×640: 가장 긴 문장 5개 + 100자 답변에서도 기록 확인/빈칸 입력/기록 완료의 카드/입력/버튼 잘림 없음. 세 단계 콘텐츠 묶음의 위치 차이 0px.
- 390×844: 스크롤 선택 UI 대신 큰 화면 안내. 창 크기를 늘리면 선택 UI 정상 복귀.
- REPORT 01: 세 데스크톱 크기와 좁은 화면에서 내용·마무리·페이지·버튼 비중첩. 긴 문장 5개 + 100자 응답도 정상 스크롤로 하단 접근 가능.
- 빛: 서로 다른 사진에서 실제 분석과 저장 데이터의 위치/팔레트 일치. 단계별 화면, 모션 감소, 결과 건너뛰기, 다시 보기, 원본 비교, 상세 표시, 저장/다음 씬 통과. 다시 보기 전후 결과 캔버스 동일.
- 전체 실제 동선: 빛 선택/변환 → 계단 → 소리 → 기억 드로잉 → 문장 → 레이어 → 보고서. 선택/드로잉 보존, 보고서 재진입 생성 시각 보존, 출력용 빛 캔버스 동일 확인.
- `npm run build`, `git diff --check` 통과. 기존 500kB 번들 경고는 남아 있습니다.
- 기존 staged/unstaged 작업 보존. 영상 파일·소리 정책·분석/생성 알고리즘·관람 데이터 구조 변경 없음. reset/checkout/commit/push 없음.
- 미확인: 실제 iOS/Safari, 다른 브라우저의 글꼴 렌더링 차이. 1200×640 미만에서 전체 문장 선택을 지원한다고 주장하지 않습니다.
