# 휴대폰 전체 기록 연결

2026-11-01. 공개 배포 구조는 GitHub Pages의 정적 사이트다. Supabase 무료 저장소/API와 로컬 앱 연결을 완료했다. 사용자 요청으로 공개 프런트 배포도 완료했다. 아래 준비 과정 기록과 마지막 현재 연결 상태를 함께 참고한다.

## 지금 동작하는 기능

- 직접 담는 QR 링크(v2): 사진 ID·색 단어·소리와 위치·물건·고른 전체 문장·직접 작성한 응답·개인 해석·선택 과정 요약. 이전 v1 링크도 읽는다.
- 휴대폰 보고서: 원본 사진·빛·소리·기억의 방·문장·응답, 보고서 전체 PDF 인쇄용 표시와 네이티브 공유/복사 대체 경로.
- QR은 글자를 꾸미거나 모듈을 생략하지 않는다. 실제 데이터량에 맞춰 모듈당 정수 픽셀과 네 면 여백을 유지한다. 복잡한 패턴 자체를 크게 줄이려면 아래의 짧은 저장소 주소가 필요하다.

## 저장소를 연결하면 활성화되는 기능

`VITE_REPORT_STORAGE_ENDPOINT`를 프로젝트 소유 API 주소로 설정하고 사이트를 다시 빌드/배포한다. 예: `https://<project>.supabase.co/functions/v1/reports`.

환경 변수가 비어 있으면 업로드하지 않고 기존 직접 담는 QR을 사용한다. 설정된 경우 최종 문서의 보관 안내를 읽고 관객이 화면 기록도 함께 가져가기를 눌렀을 때만 전체 자료를 준비하고, 성공하면 `#/r/@<id>` 형식의 짧은 QR 주소로 교체한다. 실패하면 현재 직접 담는 QR을 유지하고 상태를 알린다.

API 계약:

- `POST <endpoint>`: `reportTransfer.ts`의 `TransferReport` JSON을 받아 저장하고 `{ "id": "<random-id>" }`를 반환한다. ID는 8–96자의 영문/숫자/`_`/`-`이며 충분히 추측하기 어렵게 생성한다.
- `GET <endpoint>/<id>`: 동일 JSON을 반환한다. 없는/만료된 기록은 404/410.
- JSON에는 PC와 같은 해석/근거, 실제 빛 규칙과 변화 값, 직접 남긴 그림, 각 선택 단계의 최근 화면/포인터 기록을 포함한다. 카메라·마이크 자료와 전체 분석용 행동 로그는 포함하지 않는다.
- 클라이언트 업로드 상한은 25MiB다. 프로젝트의 실제 저장 용량을 측정한 뒤 보관 기간을 결정한다. 같은 내용의 반복 POST는 서버에서 중복 저장하지 않도록 한다.
- API가 허용할 전시/개발 origin에 CORS를 설정하고, 쓰기 요청 용량·빈도를 제한한다. 서비스 역할 키는 서버의 비밀 환경 변수에만 둔다. `VITE_` 변수에는 API 주소만 넣는다.

Supabase 같은 서비스의 무료 저장소로 시작할 수 있다. 실제 서비스 선택·계정 생성·보관 기간·서버 함수 배포는 사용자가 결정한 뒤 별도로 연결해야 한다. 현재 연결 코드는 가상 요청으로 생성/조회/잘못된 자료/없는 링크 처리를 확인했으며 실제 서비스 연결 완료를 뜻하지 않는다.

## 검증 범위

- 직접 담는 QR의 새/이전 형식, 선택 단서 누락 방지, 작성 문장 왕복 확인.
- 전체 자료 전송 클라이언트는 가상 fetch로 테스트. 실제 네트워크 업로드 없음.
- 휴대폰 선택 화면 재생은 저장소에 실제 파일을 보관하고 새 공개 사이트를 배포한 뒤, PC→휴대폰 경로로 추가 검증해야 한다.

## 2026-11-01 Supabase 연결 작업

- 서버 초안: `supabase/migrations/202611010001_report_storage.sql`, `supabase/functions/reports/handler.ts`, `supabase/functions/reports/index.ts`.
- SQL은 비공개 `exhibition-reports` 버킷과 메타데이터 테이블을 만든다. 브라우저 역할에는 읽기·목록·쓰기 권한을 주지 않으며, Edge Function의 서버 전용 키만 접근한다. 48자리 무작위 주소를 가진 사람은 해당 기록을 볼 수 있으므로 QR 주소 공유 안내가 필요하다.
- 파일별 25MiB, 예약 용량 합계 800MiB, 새 기록 하루 100개, 같은 주소의 요청 분당 12회가 초기 상한이다. 네트워크 주소는 서버 비밀값/날짜와 함께 해시로만 제한 테이블에 넣고 1일 후 다음 요청에서 정리한다. 같은 본문은 중복 저장하지 않는다. IP 기반 제한은 플랫폼 전달 헤더에 의존하며 별도 봇 방어를 대체하지 않는다.
- 운영 전 보관 기간/삭제 절차와 관객의 전송 안내를 확정해야 한다. UT 활용 동의·설문 수집은 별도이며 이 서버 초안은 연구 동의를 받았다고 간주하거나 설문을 수집하지 않는다. 기존 자동 전송 코드는 환경 변수가 없으므로 여전히 비활성이다. 실제 환경 변수를 켜기 전에 관객용 전송 안내와 선택 동작을 연결한다.
- 필요한 서버 환경 변수: 기본 제공 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, 새 비밀값 `REPORT_HASH_SALT`, 선택 `REPORT_ALLOWED_ORIGINS`(쉼표 구분). 비밀값은 Vite/채팅/소스에 넣지 않는다.
- 브라우저에는 프로젝트의 로그인 세션이 없어 Supabase 로그인 화면에서 사용자의 로그인을 기다리고 있다. SQL 적용·프로젝트 생성·서버 배포·실제 저장소 왕복·프런트 환경 변수 연결은 아직 수행하지 않았다. Edge Function의 비로그인 QR 접근 설정도 실제 배포 시 확인해야 한다.
- 서버 로직은 가상 Supabase 응답으로 CORS/잘못된 본문/개별 읽기/중복 저장/한도 오류/설정 없음 처리를 확인했다. SQL은 실제 Postgres에서 실행하지 않았다.
