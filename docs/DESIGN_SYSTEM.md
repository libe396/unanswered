## 2. 전시의 중심 의미

타인의 흔적을 따라 사진·소리·물건·문장을 고르는 동안 관객 자신의 바라보는 방식이 남는다. 마지막에는 그 기록을 자신의 흔적으로 만나게 된다.

- Figma의 연결: `UNKNOWN RECORD → YOUR TRACE`.
- 중심 의미: 누구를 떠올렸든 선택의 순간에는 관객 자신이 있었다.
- 답하지 못한 빈칸도 남길 수 있다. 현재 허용 범위는 드로잉과 마지막 문장 빈칸이며, 모든 단서를 건너뛸 수 있다는 의미로 안내하지 않는다.
- 행동과 이유를 구분한다. 체류 시간에는 읽기·조작·감상 시간이 포함된다. 시간으로 성격이나 심리적 망설임을 단정하지 않는다.
- 조용한 전시 공간, 한 장면의 한 질문, 관객이 읽고 바라볼 여백을 우선한다.

## 3. 시각 문법

| Figma 원칙 | 웹에서 지킬 의미 |
| --- | --- |
| OBSCURED | 인물의 정체를 일찍 확정하지 않는다. 흐림을 쓰되 조작 안내는 읽히게 한다. |
| RESIDUAL | 빛·잔상·선택 흔적이 남는다. 보라색을 모든 면의 기본 채움으로 쓰지 않는다. |
| OBSERVATIONAL | 읽는 도중 문장을 임의로 교체하거나 서두르게 하지 않는다. |
| UNCERTAIN | 기록의 불완전성과 빈칸을 인정한다. 결과를 정답이나 성격 판정으로 제시하지 않는다. |

재료는 어두운 표면, 흐린 유리, 정적인 필름 그레인, 기록용 종이와 얇은 선이다. 움직임은 기억이 밀리고 늦게 따라오는 smear/drift, fade/dissolve를 중심으로 한다. 지속적인 회전·강한 번쩍임·과장된 튀는 움직임을 추가하지 않는다.

기존 입자 인물, 빛 변환, 소리 유리돔, 기억의 방 선화, 문장 카드, 기록 레이어, 조사원증, 근거별 유리 기록물을 보존한다. 각 오브젝트의 형태까지 하나의 일반 카드로 통일하지 않는다.

## 4. 전시 동선과 역할

| 구간 | 관객의 행동·의미 | 보존 사항 |
| --- | --- | --- |
| Landing | 아직 알 수 없는 존재를 바라보고 입장 | 현재 초상·입자 탐색·입장 반응 |
| ZONE 01 | 엘리베이터 → 인트로 영상 → 조사 편지 | 순서, 영상 전체 관람, 음성 재생. SKIP/소리 끄기 재도입 금지 |

| ZONE 03 | 사진 1개 → 감정 단어 최대 2개 → 빛 변환·저장 | 단어 0개에서는 진행 불가, 기존 변환과 저장 |
| ZONE 04 | 일곱 소리 탐색 → 하나 선택 → 기억 속 위치 표시 | 가로 선명도·세로 거리, 재생과 지도 구분, BACK으로 돔 복귀 |
| ZONE 05 | 물건 2개 이상 선택 → 공간에 덧그리기 또는 생략 | 방 선화·선택/해제·그림 저장과 생략 |
| ZONE 06 | 20개 문장에서 3–5개 선택 → 복원 → 빈칸 응답 또는 생략 | 기존 문장·선택 순서·끝 문장 조건·기록 |
| ZONE 07 | 모은 기록의 레이어 확인 | 앞서 남긴 단서와의 연결 |
| ZONE 08 | 카메라 선택 → 공개 → 조사 방식 → 발견 → 마무리 → 상세 문서 | 근거에 따른 발견 0–3개, QR 요약본·인쇄·재시작 |

내부 장면 ID와 관객에게 보이는 ZONE 번호는 다르다. `zone03Intro`는 소리 공간으로 이어지는 내부 장면이며 별도 전시 구간을 추가하지 않는다. 사용하지 않는 `recordLayerFirstVisit`을 다시 동선에 넣지 않는다.

새로고침/재접속은 Landing에서 시작한다. 중간 진입 영상 7개는 현재 모두 `mode: none`이며 원본 파일은 보존한다. 인트로·사진의 빛 변환·최종 공개는 유지한다.

## 5. 색상 — Figma와 현재 웹의 대응

아래 Figma 값은 Color System 보드에서 확인한 값이다. 현재 웹값을 Figma 값으로 자동 교체하지 않는다. 화면과 출력물은 역할을 공유하며 각각의 매체에 맞는 값을 사용한다.

| 역할 | Figma Screen | Figma Print | 현재 웹 토큰/값 |
| --- | --- | --- | --- |
| 작업/깊은 배경 | `#07050E` | `#DEDCE6` | `--bg-void: #070709` |
| 장면 배경 | `#0A0714` | `#F4F3F7` | `--bg-base: #0B0B0E` |
| 불투명 면 | `#150F26` | `#FFFFFF` | `--bg-elevated: #131317` |
| 기본 경계 | `#2A1F4E` | `#C8C5D4` | `--line: rgba(255,255,255,.11)` |
| 관객의 흔적 | `#8A6BFF` | `#5B41C4` | `--trace: #AB93FF` |
| 제목·본문 | 표기 `#F2EEFF`* | `#17141F` | `--text-primary: #EDECF2` |
| 보조 설명 | `#9C93B8` | `#6B6580` | `--text-secondary: #B8B5C2`, `--text-tertiary: #AAA6B5` |

*Figma 본문색은 보드에 적힌 `#F2EEFF`와 디자인 컨텍스트의 바인딩 색 `#E4DFF6`가 다르다. 확정값으로 단정하지 않는다.

현재 웹의 유리면은 흰색 3.5%/5.5%, 경계는 7%/11%/20%다. 반사 그라데이션을 일반 패널에 반복 추가하지 않는다. 공용 유리의 blur는 24px이며 계속 움직이는 요소에 무분별하게 적용하지 않는다. 보라색 잔광은 주요 오브젝트 뒤의 제한적인 조명이다. 소리 장면에서 제거한 잔상/선반을 공통 규칙을 이유로 다시 넣지 않는다.

사진에서 추출한 색과 관객이 만든 빛의 팔레트는 작품 데이터다. UI 색상 통일을 위해 바꾸지 않는다. Landing/엘리베이터의 신호색 `#9FB2F2`도 별도 역할로 보존한다.

## 6. 서체와 글자 크기

- 한글·긴 문장·일반 UI: Pretendard. 한글에 넓은 영문 자간이나 대문자 변환을 적용하지 않는다.
- 짧은 영문 표식·기록 번호·ZONE·BACK: Bebas Neue. 현재 `--font-display`와 `--font-mono` 모두 Bebas Neue를 사용한다. 이름이 mono라는 이유로 IBM Plex Mono로 바꾸지 않는다.
- 긴 메타데이터는 읽기 위한 본문 서체를 우선한다.
- Figma 보드의 대형 표본 크기를 웹에 그대로 옮기지 않는다. 현재 크기를 유지한 상태에서 실제 화면의 구체적인 문제를 확인한 뒤 수정한다.

| 현재 웹 토큰 | 기본 루트 16px에서의 크기 |
| --- | --- |
| `--type-meta` | 12px |
| `--type-body`, `--type-button` | 16px |
| `--type-body-lg` | 18px |
| `--type-title-sm` | 22px |
| `--type-title` | 28px |
| `--type-display` | 48px |

Figma 표본은 영문 72/52/36px, 한글 제목 36/26px, 본문 19/16px, 캡션 14px, 메타 17px다. 한글 표본은 행간 150%·자간 -2%를 안내한다. 현재 Stage 질문은 22px·행간 1.4, 설명은 16px·행간 1.7이다. 이것은 확인된 차이이며 전역 확대 지시가 아니다.

### 2026-11-01 역할 스케일 (Landing 제외)

같은 역할은 모든 화면에서 같은 값을 쓴다. 창 폭에 따라 바뀌는 vw clamp는 Landing에만 허용한다.

| 역할 | 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- | --- |
| Statement | `--type-statement` | 32px / 400 | 보고서의 한 문장 화면, 공개 |
| Question | `--type-question`, `--weight-question` | 22px / 500 | 장면 질문, 카메라 선택, 최종 문서 소제목 |
| Body | `--type-body` (`--type-body-lg`) | 16px (18px) / 400 | 설명, 문서 본문, 등록 지침(18) |
| Label | `--type-label` | 13px / 400–500 | 한글 보조 라벨: 존 이름, 단계, HUD, 소리 이름, 캡션 |
| Code | `--type-meta` | 12px Bebas | ZONE, RPT, BACK, 01 / 05 |

최종 문서 제목만 2.75rem 고정. 640px 이하의 기존 모바일 축소 규칙은 유지한다. 한글을 12px 이하로 두지 않는다.

## 7. 배치·간격·컴포넌트

- 간격 토큰: 4/8/12/16/24/32/40/48/64/96px. 모서리: 0/4/8/12px.
- 기본 Stage: 최대 960px, 작품 열 392px, 열 간격 96px. 기억의 방은 별도 wide 배치를 유지한다.
- 2026-11-01 공통 프레임(최종): 상호작용 장면은 `--stage-frame` 1120px·좌우 최소 `--stage-gutter` 48px 안에 둔다. 질문 영역은 좌측 정렬로 프레임 왼쪽 위(y=`--stage-top` + `--stage-head-offset`: 높이 900px 이상 +40px, 800px 이하 0)에 고정하고(행간 1.4/1.4/1.5), 컨텐츠는 프레임 폭을 채운 채 질문 아래 남은 높이의 가운데에 둔다. 두 열 Stage는 1fr/1fr·간격 96px, 오브젝트는 열 안 가운데. 문장 도입·기록 레이어·카메라 선택·보고서 한 문장 화면은 인트로/요약 구도로 예외. 주 버튼은 읽는 순서의 끝.
- 2026-11-03 부스 iMac 예외: `@media (min-width: 1800px) and (min-height: 1000px)`에서만 질문~버튼 묶음 전체를 상단 88·하단 72 사이 세로 가운데(`safe center`)에 두고 `--stage-head-offset`은 0. 빛 분석 단계는 가운데 정렬이며 질문 높이를 앞 단계와 맞춘다. 이 밖의 화면 크기는 위 규칙 그대로.
- 기본 상단 여유 88px, 하단 여유 72px, HUD 회피 88px. 질문·작품·버튼이 고정 내비게이션 아래로 들어가지 않게 한다.
- StageHeader: 공간 이름 → 질문 → 짧은 행동 안내. 주 행동은 하나로 읽히게 하고 조건 안내를 중복 나열하지 않는다.
- 좁거나 낮은 화면에서는 장면 내부 스크롤과 기존 반응형 배치를 유지한다. 글자를 일괄 축소해 끼워 맞추지 않는다.
- PC 전시 경험이 우선이며 QR 모바일 요약본은 별도 확인한다. 이번 문서는 모바일 전시 전체 재설계를 요청하지 않는다.

## 8. 행동 상태와 버튼

| 상태 | Figma의 의미 | 적용 기준 |
| --- | --- | --- |
| IDLE | 중립·기본 면/경계 | 선택되지 않은 상태 |
| DWELL | 머무름·약한 잔상 | 호버/탐색 반응. 확정 선택과 구분 |
| SELECT | 선택·trace 경계와 표시 | 색 외에 체크·번호·선택 상태도 유지 |
| DRAW | 개입·선과 단어에 흔적 | 직접 남긴 기록. 모든 클릭을 새 기록처럼 과장하지 않음 |

현재 Primary는 중립 유리면 + 얇은 경계 + 보라색 점이다. hover는 보라 경계/빛, active는 보라 채움과 어두운 글자, disabled는 35% 불투명도다. 기본 높이 48px, 모서리 0, 좌우 여백 24px이다. Secondary와 Text는 보조 행동에 사용한다.

비활성 버튼에는 사진·단어·이름 등 충족할 조건을 보여 주고, 충족 후 행동 문구로 바뀐다. 선택된 단어는 hover 중에도 선택 표현을 유지한다. 키보드 초점은 선택 여부와 별도로 표시한다. Figma의 일반 `SKIP THIS CLUE` 예시는 모든 장면에 생략 기능을 추가하는 근거가 아니다.

## 9. 카피·보고서·카메라

- 문장형 안내는 자연스러운 합니다체, 제목·라벨은 간결한 명사형을 사용한다. 명사형 제목에 불필요한 온점을 추가하지 않는다.
- 화면에는 ‘고르기·그리기·물건·빈칸·모은 기록’처럼 행동을 알 수 있는 말을 우선한다. 현재 존 이름의 ‘흔적’은 유지한다.
- 발견은 기존 기록이 뒷받침하는 범위만 설명한다. 근거가 부족하면 부족함을 표시한다. 발견 수를 채우기 위해 해석을 만들지 않는다.
- PC 마지막 문서의 기록·근거·사진은 펼쳐 보인다. ‘내 기록 살펴보기’ 창은 밝은 읽기 면, 내부 스크롤·닫기 접근·초점 제한·Escape 후 복귀를 유지한다.
- QR은 모바일 요약본, PC는 상세 문서, 인쇄는 기존 출력 경로다. 표현을 바꾸면서 기록 원문·측정값·링크 호환을 잃지 않는다.

카메라 동의는 최종 공개 직전에 두며 아래 문구를 그대로 유지한다.

> 다음 장면에서 카메라로 내 모습을 실시간으로 볼 수 있습니다. 영상은 저장·전송하지 않으며 마이크는 사용하지 않습니다.

버튼: `카메라로 보기` / `카메라 없이 계속`. 영상 준비 후 공개를 시작하며 실패/거절 시 남긴 단서로 이어간다. 녹화·전송·마이크 요청을 추가하지 않고 퇴장 시 스트림을 종료한다.

일곱 소리와 SOUND_01–SOUND_07 ID, 지하철·자동차의 기존 SVG를 유지한다. 새 소리 선택지를 추가하지 않는다.

## 10. 움직임과 검증

일반 장면 전환은 현재 0.9초, 빠른 상태 변화는 0.2초다. 전시장 모드(`?venue=1`)는 2분 무입력 시 처음으로 돌아간다(1분 45초 확인창 + 15초, 최종보고서는 2분 자동 초기화, 2026-11-03). Landing→엘리베이터의 연속 입장은 별도 전환으로 보존한다. 움직임 줄이기 경로를 유지한다. 보고서 읽기는 관객의 버튼 진행을 존중하고 불필요한 읽기 잠금을 추가하지 않는다.

약 5분은 설계 목표다. 기존 도구 조작 1회 5분 39초 기록은 신규 관객 평균이 아니며 상세 보고서 읽기·QR 저장도 포함하지 않았다. 강제 종료나 카운트다운을 추가하지 않는다.

장면별 수정 후 실제 브라우저에서 진입 → 탐색 → 선택/해제 → 조건 충족 → 다음 장면 → BACK/재진입의 영향을 확인한다. 새로고침 후 Landing도 확인한다. 보고서 변경 시 근거 창·하단 접근·QR/인쇄의 영향 범위를 별도로 점검한다. 빌드만으로 시각/동선 검증을 완료 처리하지 않는다.

## 11. 다음 피드백에서 결정할 사항

1. 구체적으로 어느 장면의 질문·작품·버튼 배치가 흐름을 끊는지 실제 화면을 기준으로 지정한다.

## 12. 2026-11-01 Landing 마감 반영

- 사용자 요청: 현재 구도를 조금 다듬고, 수정된 로고의 오른쪽 보라색 언더바를 제외한다.

- 제목 크기·문구·인물 위치는 유지한다. 행간 1.28, 본문 시작 32dvh, 데스크톱 로고 144px/상단 40px로 정리했다. 전시 소개는 같은 상단 여백과 바깥 정렬을 사용한다.
- 입장 버튼은 최소 폭 208px, 위 간격 32px, 중립색 밑줄을 사용하며 hover/focus에서 trace 색과 화살표의 2px 반응을 보여 준다. 움직임 줄이기에서는 화살표 이동을 생략한다. 관람 시간 앞에는 짧은 중립색 구분선을 둔다.

### 같은 날 후속 피드백: 제목 비중 축소

- 사용자가 제목이 너무 크고 현재 표현이 덜 트렌디하다고 지적했다. 앞선 ‘제목 크기 유지’는 이번 사용자 요청으로 변경한다.
- 제목은 데스크톱 `clamp(32px, 3.3vw, 48px)`, 굵기 400, 행간 1.4, 자간 -0.04em이다. 1280px 폭에서는 56.32→42.24px로 25% 줄었다. 본문 시작은 35dvh로 조정해 축소된 텍스트와 인물 사이의 여백을 유지한다.
- 모바일 제목은 26–36px, 낮은 PC 창은 30–40px로 축소한다. 안내문·입장 버튼은 14px, 버튼 최소 폭은 176px이며 높이 52px을 유지한다. 큰 표제의 강조를 줄이고 인물을 중심으로 읽히게 한다.
- 최신 로고·카피·인물의 크기/위치·입장 연출·다른 장면은 유지한다. 모바일/낮은 창은 코드 규칙만 확인했으며 이번 브라우저 실측은 1280×720이다.

### 구도 비교 시안 — 미채택

- 사용자 요청으로 같은 원본 로고·인물을 사용한 두 안을 별도 제작했다. 개발용 미리보기는 `lab/landing-directions.html`이다. Vite 배포 입력이나 실제 Landing에는 연결하지 않았다.
- 포스터: 작은 한글 제목, 인물의 아래를 가로지르는 큰 워드마크. 로고와 이미지가 하나의 포스터를 이루는 방향이다.
- 갤러리: 중앙의 작은 인물과 넓은 검은 여백, 하단 제목/입장 버튼. 이미지에 집중하고 안내는 하단에서 읽는 방향이다.
- 대화 내 비교 시안은 제목/인물 크기 조절을 지원한다. 미리보기의 입장 안내는 구도 확인용이며 실제 전시 조사/저장·음향·카메라 기능을 실행하지 않는다. 사용자 선택 전까지 둘 다 확정 기준이 아니다.

### 2026-11-01 확정: 글라스 기록 카드 Landing

사용자가 Claude와 확정한 `lab/landing-scan.html`을 실제 `LandingScene`으로 옮겼다. 아래는 이번에 확정된 결정이며 Landing에만 적용한다.

- **Landing만 뷰포트 비례 크기를 쓴다.** 고정 px 상한 없이 `vw`/`vh`/`clamp`로 화면에 비례한다. 기준 부스 화면은 iMac 24" 전체화면 2240×1260이고 1440×900·1280×720에서도 같은 비율로 보인다. 6장의 전역 타입 토큰(`--type-*`)과 공용 스타일은 바꾸지 않는다. 이 예외는 다른 장면으로 확장하지 않는다.
- **제목 굵기 450.** Pretendard Variable, `clamp(32px, 3.3vw, 76px)`, 행간 1.28, 자간 -0.035em. 한 글자씩 타이핑하고 줄바꿈에서 420ms 멈춘다. 앞선 ‘제목 비중 축소’(weight 400 / 최대 48px)는 이번 확정 시안으로 대체된다.
- **타이핑 커서는 `#AA8EEE`,** 1.05초 점멸. 기준 시안의 `#8A6BFF`와 작업 지시 검증 항목의 `#AA8EEE`가 달라 사용자에게 확인했고, 사용자가 `#AA8EEE`를 선택했다. 이 값은 커서에만 적용한다. 카드 뒤 보라 빛은 시안대로 `rgba(138,107,255,.055)`를 유지하고, 공용 `--trace`(#AB93FF)는 `전시 소개` 화살표와 시작 안내 앞 선에 유지한다.
- **입장은 버튼이 아니라 화면 클릭이다.** 화면 어디를 눌러도 입장하며 `전시 소개` 링크와 6px 이상 드래그는 제외한다. Enter 키로도 입장하고, 시작 안내(`CLICK ANYWHERE TO BEGIN` + `클릭하면 조사가 시작됩니다 · 약 5분`)는 초점 링을 보이는 실제 버튼이다. 기존 `단서 따라가기` 버튼과 별도의 `약 5분의 온라인 전시` 줄은 없앴다. 입장 연출은 기존 1.3초 안에서 카드가 흐려지며 빛 입자로 풀리도록 맞췄고 새 대기 시간은 없다.
- **포스터/갤러리 비교 시안은 폐기한다.** 위 ‘구도 비교 시안 — 미채택’ 항목은 종료로 처리한다. `lab/landing-directions.html`은 기록으로만 남긴다.
- 터치 기기(`(hover: none) and (pointer: coarse)`, 화면 폭이 아니다)에서는 시작 안내 자리에 PC 관람 권장 문구와 `링크 복사`, 작은 `그래도 계속 보기`를 보이고 화면 클릭 입장을 끈다. Landing에만 적용하며 QR 모바일 보고서 경로는 바꾸지 않는다.
- 새 컴포넌트는 `src/components/LandingRecordCard.tsx`/`.css`다. `LandingPortrait.tsx`는 Landing에서 더 이상 쓰지 않지만 파일은 남겨 둔다. 변경과 검증 범위는 두 피드백 문서의 같은 날짜 기록을 따른다.
