# 이야기 흐름 / 최종보고서 검증

[문장 인트로와 공개 흐름 캡처](index.html)

## 변경
- 문장 인트로에 공간 → 이야기 선택 연결을 추가. 실제 물건 이름 요약, 3~5개 선택 정책 유지. 기록이 없으면 “그 사람이 머물던 공간을 살펴보았습니다.”
- 메인 질문: “이 공간에 머물던 사람의 이야기는 어떻게 이어졌을까요?”
- 기존 보고서 수렴 부분에서 최대 3개의 실제 행동 사례를 보여줌. 새 추적 항목이나 저장 키 없음.
- 공개 전 두 문장 → 기존 카메라 동의 → “이 보고서에 남은 흔적의 주인은,” → “당신입니다.” → 공개 후 설명 → “보고서에 적히는 것은 결론이 아니라 흔적입니다.”
- 화면 영수증과 인쇄 보고서도 같은 사례 계산을 사용하고, 소유자 라벨을 “흔적을 남긴 관객”으로 명시.
- 선택 키워드를 근거로 오래 머물렀다고 단정하던 기존 관찰문을 확인 가능한 선택 설명으로 교체.

## 활용 데이터와 결측 처리
- 문장: 저장된 dwellTimes와 selectedSentenceIds. 기존 sentenceDwellNote의 2.5초 이상·유일한 최장 체류 기준 재사용. 동률, 누락, 미선택, 잘못된 ID는 제외. 초 단위는 기존과 같은 소수점 한 자리.
- 물건: memorySketch 행동 로그의 object 그룹에서 같은 ID의 select 다음 deselect가 확인된 경우만 표시. 선택 없이 해제만 있거나 select 반복이면 표시하지 않음.
- 소리: 행동 로그가 있으면 기존 summarizeSound의 replayCountBySound 재사용. 이전 청취 1초 이상, 새 재생 0.8초 이상이며 이어듣기가 아닌 기존 판정 유지. 원시 로그가 없으면 저장된 replayCount 사용.
- 행동 근거가 없으면 실제 선택한 문장·소리·물건만 최대 3개 표시. 선택도 없으면 “확인할 수 있는 선택 기록이 없습니다.” 시간을 만들지 않음.
- 공개 전에도 유효한 체류 사례가 없으면 “선택과 머무름” 대신 “선택의 흔적” 사용.

## 검증
- npm run build, git diff --check 통과 (기존 번들 크기 경고 유지).
- 실제 UI의 물건 2개 선택 → 저장 → 문장 인트로 진입 및 선택 이름 표시.
- 빈 물건 기록 안내, 문장 최소/최대 정책 3~5개 유지.
- 1366×768 및 1100×650: 20개 문장, 최대 5개 선택, 다음 버튼 노출. 페이지/카드 스크롤 및 텍스트 잘림 없음. 작은 높이는 질문을 기존 헤더의 중앙 여백에 배치.
- 390×844: 인트로, 행동 사례, 카메라 동의, 공개, 후속 설명과 마지막 버튼 캡처 검토. 문장 비교는 기존 데스크톱 전용 안내 유지.
- 판정 테스트: 유효한 세 사례, 빈 데이터, 체류 동률/누락, 선택 없이 해제, 반복 선택, 이어듣기, 짧은 재생. 부정 사례에서 거짓 행동 사례 없음.
- 가상 카메라 허용, 카메라 미사용, 권한 거부: 같은 최종 설명까지 진행. 동의 전 요청 0회, audio:false, 최종보고서로 이동 후 트랙 종료.
- 일반 모션에서 권한 대기를 지연시켜 공개가 진행되지 않음을 확인. 영상 준비 후 공개 진행, 도중 다른 Zone 진입 시 트랙 종료 확인.
- 빈 보고서 화면과 인쇄 문구 일치, 인쇄 PDF 생성 성공. 물리 인쇄물의 페이지 구성은 실기 미검증.
- 실제 웹캠·실제 휴대폰·Safari는 미검증. 모든 테스트는 격리된 브라우저 저장소 사용.
